# Review record — S3 identity layer (2026-10-02)

Builder: codex `gpt-6-astra` from a fable-written spec; three Astra (xhigh, read-only) rounds + the session's reads; `./gradlew build` under Docker after every round (56 tests at the end, Testcontainers Postgres 16).

| Round | Outcome |
|---|---|
| 1 — Astra: **DO NOT MERGE** (1 P1, 4 P2) | P1 a stale-but-valid bearer could complete a `rotate`/`withdraw` after a concurrent rotation or revocation → mutations now re-check `key_hash` + `revoked_at` inside their own transaction (`UPDATE … WHERE key_hash = ?`, `SELECT … FOR UPDATE`); P2 rejected auth bypassed Ktor's rate limiter (it checks `isHandled` first) while still reaching the DB → cheap checks first + an admission limiter before any I/O; P2 `last_seen_day` written before the signature verified → lookup/touch split, touch only after verification; P2 `/v1/me` mixed two instants across midnight → one instant; P2 privacy/constant-time tests could not fail → recursive throwable-chain + rendered-log assertions, a constant-time source guard; speculative budget race → atomic single-statement `tryConsume`. |
| 2 — Astra delta: **DO NOT MERGE** (1 P1, 2 P2) | P1 the admission LRU was churnable (fresh random ids got fresh buckets; eviction forgave an exhausted bucket) → a GLOBAL 600/min bucket + a 32-permit in-flight semaphore before body/DB work, eviction only of ≥ half-full buckets else fail-closed deny (known-id starvation accepted and documented: the id is 128 random bits and the authenticated quota is separate); P2 the `PrivateThrowableFilter` codex added DROPPED every exception-bearing log event → replaced by `SafeThrowableConverter` (exception class chain + the outermost throwable's first 3 frames, never a message; verified on a real bad-URL startup: `FlywaySqlUnableToConnectToDbException <- PSQLException <- ConnectException`); P2 `last_seen_day <> ?` could move activity backwards → `last_seen_day < ?` bound to `key_hash` and `revoked_at IS NULL`; hardening: `Install.toString` redacts the hash; one request instant via a call attribute. SQL `key_hash = ?` equality is a concurrency precondition after the constant-time check, not itself constant-time (stated). |
| 3 — Astra delta: **DO NOT MERGE** (1 P1, 2 P2) | P1 the body read ran WITHOUT a deadline while holding an in-flight permit (32 dripping bodies with an invented bearer park every permit) → `readBounded` with a 10 s total deadline (`BoundedRead.Ok/TooLarge/Timeout`, 408 on timeout, permit released in `finally`; `BoundedBodyReadTest` incl. a dripping body); P2 `/v1/me` re-read by UUID alone and could disclose a replacement generation's state to an old credential → `InstallStore.lookupActive(id, keyHash)` (credential-bound, active-generation read) + 401 on miss; P2 same-key enrol wrote `last_seen_day` unconditionally → `GREATEST(last_seen_day, ?)`; both covered by store-level tests. Also: the per-id bucket now decides BEFORE the global one (an exhausted id can no longer drain the global budget), and a globally denied never-admitted id leaves no resident bucket. Documented trade-off (Astra): one invented id can still spend the 600/min global budget and compete for every refill — the authenticated quota has no reserved capacity; per-IP fairness is the edge's job (not in this slice). Round 4 fixes were applied by the session (fable) rather than codex; a final delta pass runs in parallel with CI and any NEW finding is filed, not looped (convergence rule). |

Not in this slice (documented): per-IP edge rate limiting (needs a custom Caddy build); replay protection beyond the ±300 s window is the S4 batch ledger.
